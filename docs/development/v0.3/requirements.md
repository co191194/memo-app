## 3. 背景、利用者、利用場面

### 背景

v0.2までに、ローカルのJSONファイルに保存したメモをCLIで追加・編集・一覧・詳細表示・検索・削除できるようになった。v0.3では、同じメモをブラウザから閲覧できるMPA構成のWeb画面を追加する。

v0.3の主目的はGoの学習である。HTTPサーバー、サーバーサイドでのHTML描画、CLIとWebで処理を共有する設計を題材にする。

### 利用者

- 個人用メモをCLIとブラウザで管理するプロジェクト所有者
- memo-appを題材にGoを学ぶプロジェクト所有者

### 主な利用場面

1. 保存済みメモの一覧をブラウザで眺め、目的のメモを探す。
2. 長い本文を含むメモの内容を、ブラウザで読みやすく表示する。
3. CLIで追加・編集したメモを、そのままブラウザで確認する。

長い本文をフォームで書く利用場面は、Webからの追加・編集を扱うv0.4以降で対象とする（[Q-R02](#9-決定事項未決事項)）。

## 5. v0.3全体の成功条件

次のすべてを満たしたとき、v0.3の要件を満たしたと判断する。

1. R-01からR-07に対応する受け入れ基準がSpecに定義され、検証済みである。
2. v0.3マイルストーンに含まれる実装・テスト・利用者向け文書のIssueが完了している。
3. 既存JSONデータを移行操作なしで利用でき、既存CLIコマンドの互換性が保たれている。
4. GitHub Actionsで書式、静的解析、race detector付きテスト、ビルドが成功している。

## 6. 対象外

v0.3では次を実装しない。

- Webからのメモの追加・編集・削除（v0.4以降で検討。[Q-R02](#9-決定事項未決事項)）
- Webからの検索
- 認証、外部ネットワークへの公開
- CLIとWebサーバーを同時に使ったときの競合への対策
- サーバー内の排他制御（`sync.Mutex`）。Webからの書き込みを扱うv0.4で対象とする（[Q-R03](#9-決定事項未決事項)）
- Markdownの描画（本文はプレーンテキストとして表示する）
- SPA化、フロントエンドフレームワークの導入
- CLIのサービス層への移行（別Issueで扱う。時期は未定）
- タグ・カテゴリ機能、SQLite対応、TUI

## 7. 制約

- メモはローカルのJSONファイルに保存し、既存のJSONフィールドとその意味を維持する。
- 既存のCLIコマンドの形式と外部から見える動作を、明示した仕様変更なしに壊さない。
- Webサーバーは既定でループバックアドレス（`127.0.0.1`）だけで待ち受ける。
- 標準ライブラリだけを使い、新しい依存パッケージを追加しない。
- メモの内容をHTMLに出力するときは、エスケープして表示する。
- CLIがメモを保存している間にWebが読み込む場合は、既存の保存方式（一時ファイルに書き出してから置き換える）に依存し、追加の対策は行わない。
- Requirement、Spec、実装、受け入れの承認を推測せず、プロジェクト所有者の明示した判断を記録する。
- #42では実装コードの変更を行わない。

## 8. 学習目標

1. `net/http` と `ServeMux` を使い、HTTPリクエストの処理とルーティングを実装できる。
2. `html/template` と `embed` を使い、サーバーサイドでHTMLを描画し、テンプレートや静的ファイルをバイナリに同梱できる。
3. サービス層を設計し、CLIとWebでメモ操作の処理を共有できる。排他制御はv0.4で扱う（[Q-R03](#9-決定事項未決事項)）。
4. `net/http/httptest` を使ったHTTPのテストを読み、何をどのように検証しているかを理解できる。テストの実装はエージェントが担う（[10章](#10-開発の進め方)）。

学習目標の達成状況は、理解確認を行わないため、プロジェクト所有者の自己評価とする。

## 10. 開発の進め方

プロジェクト所有者が2026-10-16に示した方針による。

- TDDを原則とする。ただしテストは最小限の正常系から始め、エッジケースは正常系の実装後に追加する。
- テストはエージェントが実装し、プロダクトコードはプロジェクト所有者が実装する。
- エージェントはテストを追加するとき、各テストが何をどのように検証しているかをPRの説明に記載する（学習目標4のため）。
- 理解確認は行わない。
