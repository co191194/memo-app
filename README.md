# memo

ローカルのJSONファイルにMarkdown形式のメモを保存する、個人用のGo製ツールです。CLIでタイトルと本文の追加・編集、一覧・詳細表示・検索・削除、保存先の切り替えができます。v0.3からは `memo serve` でローカルのWebサーバーを起動し、メモの一覧と詳細をブラウザで閲覧できます。

## セットアップ

Go 1.26.4以降が必要です（[go.mod](go.mod)を参照）。リポジトリを取得してビルドします。

```bash
git clone https://github.com/co191194/memo-app.git
cd memo-app
go build -o memo ./cmd/memo
```

以下の例では、ビルドした `./memo` を使います。`memo` を実行したい場合は、バイナリを `PATH` の通った場所へ置いてください。リポジトリには `go.mod` があるため、`go mod init` は不要です。

```bash
./memo add "Goのメモ" --body "interfaceについて調べる"
./memo show 1
./memo search interface
./memo edit 1 --body "interfaceと実装について調べる"
./memo list
```

初期設定では `~/.memo/memos.json` に保存します。ファイルがまだない場合はメモ0件として扱い、初回の保存時に親ディレクトリとファイルを作成します。既存のメモを削除したくない場合は、以下の `MEMO_PATH` で別の保存先を指定して試してください。

## コマンド一覧

| コマンド | 説明 |
|---|---|
| `./memo add <title> [--body <body>]` | メモを追加する |
| `./memo edit <id> [--title <title>] [--body <body>]` | 指定したメモを編集する（少なくとも一方のオプションが必要） |
| `./memo list` | メモのID・タイトル・作成日を一覧表示する |
| `./memo show <id>` | タイトル・本文・作成日時・更新日時などを表示する |
| `./memo search <keyword>` | タイトルまたは本文から検索する |
| `./memo delete <id>` | 指定したメモを削除する（確認なし） |
| `./memo serve [--port <port>]` | ローカルのWebサーバーを起動し、ブラウザでメモを閲覧する（[後述](#ブラウザで閲覧するmemo-serve)） |
| `./memo help` | コマンド一覧を表示する |

個別の使い方は `./memo <command> --help` でも確認できます。IDは1以上の整数です。

### 追加・表示・検索

```bash
./memo add "Goのメモ" --body "interfaceについて調べる"
./memo add "タイトルのみのメモ"
./memo add "複数行のメモ" --body $'1行目\n2行目'
./memo list
./memo show 1
./memo search interface
```

`--body` を省略したときの本文は空文字です。本文の改行もそのまま保存され、`show` で表示できます（上の `$'…'` はBashの記法です）。`search` は大文字・小文字を区別します。追加時の作成日時と更新日時は同じです。`list` と `search` はID・タイトル・作成日を表示し、`show` は本文を含む詳細を表示します。

### 編集・削除

```bash
./memo edit 1 --title "新しいタイトル"
./memo edit 1 --body "更新後の本文"
./memo edit 1 --title "タイトル" --body "本文"
./memo edit 1 --body ""  # 本文を空にする
./memo show 1
./memo delete 1
```

編集では指定していない項目は変更しません。IDと作成日時は維持し、更新日時を編集時刻に変更します（同じ値を指定した場合も更新します）。`--title` の空文字・空白のみの指定、更新項目なし、存在しないIDはエラーになります。`add`、`edit`、`delete` は成功時に出力しません。

## ブラウザで閲覧する（`memo serve`）

`serve` でローカルのWebサーバーを起動すると、保存済みのメモをブラウザで閲覧できます。

```bash
./memo serve
# Listening on http://127.0.0.1:8080
```

表示されたURL（http://127.0.0.1:8080）をブラウザで開いてください。停止するには、起動したターミナルで `Ctrl+C` を押します。SIGINT・SIGTERMを受けると新しい接続の受け付けをやめ、処理中のリクエストを最大5秒待ってから終了します（終了コード0）。

### ポートを変える（`--port`）

```bash
./memo serve --port 3000
./memo serve --port 0   # 空いているポートをOSが選ぶ
```

既定のポートは `8080` です。`0` から `65535` までを指定でき、`0` の場合は起動メッセージに実際のポート番号が表示されます。範囲外の値、数値でない値、使用中のポートを指定した場合は、エラーを表示して終了します（終了コード1）。

### 保存先

保存先の決め方はCLIと同じです。`MEMO_PATH` を指定した場合は、そのファイルのメモを表示します。

```bash
MEMO_PATH=/tmp/work-memos.json ./memo serve
```

メモは画面を表示するたびに保存先から読み込みます。サーバーを起動したままCLIでメモを追加・編集しても、ブラウザでページを再読み込みすれば反映されます。

### 画面

| URL | 内容 |
|---|---|
| `/` | `/memos` へ移動する |
| `/memos` | メモの一覧。ID・タイトル・作成日を保存した順に表示し、タイトルから詳細へ移動できる。メモが0件（保存先ファイルがない場合を含む）のときは「メモはありません」と表示する |
| `/memos/{id}` | メモの詳細。タイトル・ID・作成日時・更新日時・本文を表示する。本文は改行や空白をそのまま表示し、長い行は画面の幅で折り返す。本文が空のときは「本文はありません」と表示する |

存在しないIDや不正なIDを開くと「メモが見つかりません」、定義されていないURLを開くと「ページが見つかりません」と表示します。保存先のJSONが不正などの理由で読み込めない場合は「メモを読み込めませんでした」と表示し、エラーの詳細はサーバーを起動したターミナル（標準エラー）に1行で出力します。サーバーは止まらず、保存先を直せば次の表示から正しく表示されます。

### 制約

- サーバーは `127.0.0.1` だけで待ち受けます。同じPCのブラウザからだけ接続でき、ほかの端末からは接続できません。認証はありません。
- 閲覧専用です。メモの追加・編集・削除・検索はCLIで行ってください。Webからの追加・編集はv0.4以降で検討しています。
- 本文はMarkdownとして描画せず、書いたままのテキストとして表示します。
- JavaScriptは使っていません。アクセスログは出力しません。
- CLIとサーバーを同時に使えます。CLIは一時ファイルに書き出してから置き換える方式で保存するため、書きかけのファイルを読み込むことはありません。それ以上の同時利用の対策（排他制御など）は行っていません。

## 保存先を変更する（`MEMO_PATH`）

環境変数 `MEMO_PATH` を指定した場合、そのJSONファイルだけを読み書きします。コマンドごとに同じ値を指定するか、シェルで環境変数をエクスポートしてください。

```bash
MEMO_PATH=/tmp/work-memos.json ./memo add "Work"
MEMO_PATH=/tmp/work-memos.json ./memo list

export MEMO_PATH="$HOME/work-memos.json"
./memo list
```

未設定、空文字、空白文字だけの場合は既定の `~/.memo/memos.json` を使います。`~/` で始まるパスはホームディレクトリに展開され、相対パスは実行時のカレントディレクトリを基準とします。`~` 単独や `~user/` は展開されません。空白以外を含むパスの前後の空白は削除しません。v0.2にグローバルな `--data-file` オプションはありません。

## 保存形式と既存データ

メモはJSON配列として保存されます。主なフィールドは `id`、`title`、`body`、`created_at`、`updated_at` です。日時はRFC 3339形式です。

```json
[
  {
    "id": 1,
    "title": "Goのメモ",
    "body": "interfaceについて調べる",
    "created_at": "2026-09-27T18:00:00+09:00",
    "updated_at": "2026-09-27T18:00:00+09:00"
  }
]
```

v0.3でも保存形式は変わりません。v0.1.0・v0.2.0で保存したJSONデータは移行操作なしでそのまま読み書きできます。通常のアップデートでは既定の保存先を変える必要はありません。`MEMO_PATH` で切り替えたファイルのメモは、既定のファイルとは別に管理されます。不正なJSONや読み書きできない保存先はエラーになり、既存のJSONを上書きしません。

## 開発の背景

v0.1のMVPでは `add`、`list`、`show`、`search`、`delete` とJSONへの永続化を段階的に実装しました。当時の「これから作る」開発手順や仮のディレクトリ構成は、現行のセットアップ手順・仕様ではありません。v0.2では本文・編集・`MEMO_PATH`・CIを、v0.3ではWebでの閲覧（`memo serve`）を追加しました。過去の状態は[v0.1.0タグ](https://github.com/co191194/memo-app/tree/v0.1.0)、各バージョンの要件と受け入れ基準は開発文書（v0.2の[要件](docs/development/v0.2/requirements.md)・[仕様書](docs/development/v0.2/specification.md)、v0.3の[要件](docs/development/v0.3/requirements.md)・[仕様書](docs/development/v0.3/specification.md)）を参照してください。

現在の実装は次のように分かれています。

| ディレクトリ | 役割 |
|---|---|
| `cmd/memo` | 保存先を決め、CLIを組み立てて実行する |
| `internal/cli` | コマンドの振り分け、引数の解析、`serve` の起動と終了処理 |
| `internal/web` | ルーティング、HTTPのステータスとヘッダー、テンプレートの描画 |
| `internal/service` | 保存先からの読み込みとメモ操作の連携（現在はWebから使用） |
| `internal/memo` | メモの探索・作成・編集・削除などの操作 |
| `internal/storage` | パスの展開とJSONファイルの読み書き |
| `web` | HTMLテンプレートとCSS（`embed` でバイナリに同梱） |

将来的な拡張候補には、Webからのメモの追加・編集（v0.4で検討）、タグ機能、SQLite対応、Markdown出力などがあります。`edit`、`MEMO_PATH`、CIはv0.2で、ブラウザでの閲覧はv0.3で対応済みです。
